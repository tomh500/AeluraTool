# 安装发布版本

接收者无需安装 Visual Studio、编译器、Python 或 NuGet。发布 ZIP 中包含签名 MSIX、公开证书、Windows x64 运行依赖、PowerShell 安装向导及双击入口。

1. 将整个 ZIP 解压到本地文件夹，保留所有子目录。
2. 正常退出正在运行的遥汐工具箱和 StrikeSense，然后双击 `Install.bat`（`Install.cmd` 为兼容入口）。无需手动运行 PowerShell 命令。
3. 首次安装核对发布者与证书指纹；确认来源可信后输入 `Y`，在 Windows 管理员提示中允许证书安装。
4. 等待安装完成，通过桌面快捷方式或开始菜单启动。失败时批处理执行 `pause` 保留错误信息，包括脚本未能启动的情况，按任意键关闭。

证书只导入本地计算机的“受信任人”，不导入根证书存储。提权子进程只负责证书导入；应用和快捷方式安装到发起安装的用户。取消证书信任或 UAC 时不继续安装。若证书导入后应用安装失败，已信任的证书可能保留，脚本不会移除系统中已有依赖或卸载旧版本。

`Install.bat` 只为当前安装进程设置执行策略，不修改系统执行策略。脚本不关闭系统签名校验或安全软件；企业策略阻止安装时需联系设备管理员。自签名证书不具有公开受信任证书的发行体验，正式公开发行可改用受信任签名或 Microsoft Store。

发布包支持 Windows x64，实际最低系统版本和框架版本以包清单为准。缺少管理员权限、系统策略限制或不支持的系统仍可能无法安装；干净设备安装结果应单独验证。

安装器按主包清单核对依赖的发布者、架构、最低版本和当前用户注册状态。已满足要求的运行库跳过更新；仅提交缺失或版本不足的依赖。即使本机已装依赖，发布 ZIP 仍须附带符合清单要求的完整依赖文件。

Windows 小组件等程序可能占用共享运行库，导致 `0x80073D02`。安装器允许 Windows 延迟注册，并重新检查主包及依赖是否就绪；尚未就绪时返回 3010，提示保存工作、重启 Windows 后再次双击 `Install.bat`，不报告成功或修改快捷方式。仍报占用时保留原始错误及应用名称。脚本不会强制结束小组件、卸载系统运行库或自动重启电脑。VMware 中也应重启虚拟机内的 Windows。

## 开发与分发

- `scripts/build.ps1` 成功后自动注册对应配置的版本化本机布局，核对部署 EXE 哈希并更新桌面快捷方式；运行中的应用会阻止部署，不强制终止任务。CI 环境只构建，不注册应用或修改桌面。
- `scripts/package.ps1` 成功后同样更新本机 Release 部署。`scripts/distribute.ps1 -CertificateThumbprint <证书指纹>` 生成签名发布 ZIP，并在向导中固定该签名证书指纹。仅分发 CER 公钥证书，不导出私钥。
- 发布文件夹中运行 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Install.ps1 -CheckOnly` 可只读检查包、签名者及依赖文件是否齐全；这不等于完整安装或干净系统验证。

## Nightly 签名配置

CI 使用固定签名证书生成与手动分发相同的 ZIP；缺少签名配置、签名失败或安装预检失败时不发布。仓库 Actions secrets 需要配置 `MSIX_SIGNING_PFX_BASE64`（含私钥 PFX 文件的 Base64）与 `MSIX_SIGNING_PFX_PASSWORD`（PFX 密码）。证书必须在有效期内、可用于代码签名，Subject 匹配包 Publisher（当前 `CN=jingy`）。持续使用同一证书，避免每次更新都重新信任新证书。已有不可导出私钥的本机证书不能导出为 CI PFX；需另外准备可供 CI 使用的固定签名证书。

PFX 只在临时 runner 导入，结束时删除临时文件、证书和私钥；发布 ZIP 仅含 CER 公钥。不要将 PFX、密码或 Base64 写入仓库。旧的未签名 nightly ZIP 不能通过修改执行策略安装，需重新生成签名发布包。
