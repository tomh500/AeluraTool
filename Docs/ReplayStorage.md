# 即时重放：硬盘和内存缓存

在录屏页先关闭即时重放，再选择「临时重放缓存」为「硬盘」或「内存」，然后重新开启。选择和内存上限会立即保存，下次启动沿用；保存失败保留旧选择。原有配置默认保持硬盘模式。它只控制即时重放，自由录制和用户主动保存的视频仍写入保存目录。

| 项目 | 硬盘 | 内存 |
| --- | --- | --- |
| 平时缓冲 | 持续写入压缩 MP4 分段 | 压缩 MP4 分段直接保存在进程内存 |
| 点击保存 | 合并已有磁盘片段，成功后删除已保存的临时片段 | 从内存合并为视频，成功后释放已保存的片段 |
| 正常停止/退出 | 清理正常滚动缓存 | 释放内存片段 |
| 崩溃/断电 | 已封装片段及清单可用于恢复 | 未保存的片段无法恢复 |
| 容量不足 | 达到磁盘预留空间下限时报告错误 | 淘汰较早片段，实际可回放时长可能缩短 |

## 保存后从新画面继续

每次保存会截断并封装当前片段，导出该时刻之前尚未保存的缓冲。只有输出视频成功落到最终文件名后，才从滚动队列移除本次快照：硬盘模式删除对应临时 MP4，内存模式释放对应压缩块。保存过程中录下的新画面保留，缓存时长会从这部分重新增长；立即再保存只得到新增内容，不重复包含前一次已保存的视频。

保存失败或取消时不消费该快照，允许重试。正常滚动淘汰与容量上限仍适用，不能保证失败后所有旧内容永久留在滚动窗口。保存成功通知可点击，在文件资源管理器中打开目录并选中实际输出文件；保存中或失败的通知不会打开上一次视频。

## 写入量与 SSD 耐久度

循环删除只控制占用空间，不抵消已经发生的写入。按视频码率 15 Mbps 估算，写入约为每小时 6.75 GB、每天八小时 54 GB，另有音频、封装、配置和文件系统开销；实际编码量可能随内容变化。五分钟缓存约 562.5 MB，不意味着运行一天只写入五分钟的数据。

SSD 的影响取决于型号、使用时长和总写入量。厂商常以 TBW（累计写入量）作为有限保修条件之一，不应把该指标理解成到数值就必然报废。可对照自己 SSD 的规格和健康数据评估，参见 [Samsung SSD 保修中的 TBW 定义](https://semiconductor.samsung.com/consumer-storage/support/warranty/)。这里没有检测或推断用户实际硬盘型号，也没有承诺寿命年数。

## 内存容量与保护

默认上限 1024 MiB，可设 128–8192 MiB。该额度计算已分配的压缩片段块，包含当前片段与正在导出的快照；编码器、捕获纹理、音频和系统组件仍另占工作内存。普通滚动历史最多使用额度约 80%，其余容量为继续录制和保存提供空间。若时长与码率需要更多容量，界面显示实际缓存时长和容量受限状态，不静默改用磁盘。

每个片段使用可寻址的内存流，以 64 KiB 块分配；分配前检查共享额度，必要时释放较早的未引用片段。保存时只持有已封装片段的只读引用，不复制整份缓存；仍被导出快照使用的块也计入同一额度。极端内存不足会停止本次缓存并显示错误，用户可释放内存或降低参数后重试。

这里不创建 RAM 盘、不依赖虚拟磁盘驱动，也不先写磁盘再读回。缓冲分支不会创建 Recordings 子目录、临时 MP4、恢复 JSON 或视频输出目录。只有用户请求保存时才创建视频文件；内存导出取消或失败会清理该次导出独占创建的未完成输出，保留原有目标文件。停止内存重放不会保存恢复清单。

Windows 仍可将进程内存换出到分页文件；本功能不锁定大量物理内存、不修改系统分页设置，所以减少的是应用主动产生的持续录像写入，不能保证整台电脑完全不写 SSD。

## 实现位置

- `Tools/ScreenRecorder/Recording.Memory.*`：共享容量额度、内存 IStream、独立读取位置、封存后的只读片段。
- `Recording.Media.cpp`：将编码器输出直接封装进内存字节流。
- `Recording.Remux.cpp`：从内存字节流无损合并为视频，复用时间戳、音轨和禁止覆盖检查。
- `Recording.cpp`：滚动淘汰、并行导出快照、内存状态和停止释放。
- `Integration/RecordingPanel.cpp`：存储方式与上限的持久化、状态显示和保存失败回滚。

Media Foundation 官方支持直接向字节流写入 MP4，参见 [MFCreateSinkWriterFromURL](https://learn.microsoft.com/en-us/windows/win32/api/mfreadwrite/nf-mfreadwrite-mfcreatesinkwriterfromurl)。
